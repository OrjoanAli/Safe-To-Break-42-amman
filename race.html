Race condition

What it is

CWE-362 · OWASP category: verify on owasp.org

The shop checks if a coupon was already used, waits a moment to save it, and only then marks it as used. If two requests arrive at the same time, both pass the check, so a one-time coupon works twice.

The line

Danger: vulnerable version
        
let used = false;

        
let total = 100;

        
 

        
async function applyCoupon(code) {

        
  if (code !== "SAVE20") return "invalid";

        
  if (used) return "already used";    // check

        
  await db.save(code);                // slow step

        
  used = true;                        // marked too late causes the bug

        
  total = total - 20;

        
  return "applied";

        
}

      
        
let used = false;

        
let total = 100;

        
const lock = new Mutex();

        
 

        
async function applyCoupon(code) {

        
  return lock.run(async () => {       // one request at a time the fix

        
    if (code !== "SAVE20") return "invalid";

        
    if (used) return "already used";

        
    used = true;                      // mark it first

        
    await db.save(code);

        
    total = total - 20;

        
    return "applied";

        
  });

        
}

Highlighted line: the coupon is only marked as used after the slow step, so other requests that arrive in the meantime still see used = false.

Highlighted line: the lock makes the check and the update one step. The second request waits, then sees that the coupon is already used.
